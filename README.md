# MARKETING TREND

해외 상품 발견에서 한국 수입·총판 검토까지 기록하는 한국어 개인용 로컬 웹 앱입니다. React + TypeScript + Vite를 사용하며 계정·API 키·결제 없이 실행합니다. 인터넷 공개 배포는 포함하지 않습니다.

## 실행

Node.js 24와 npm을 사용합니다. 저장소에 잠금 파일이 포함되어 있습니다.

```sh
cd /workspace/marketing_trend
npm ci --cache /workspace/.npm-cache
npm run dev -- --port 5173 --strictPort
```

개인 컴퓨터에서는 저장소 경로로 이동 후 `npm ci`와 `npm run dev`를 사용합니다. 기본 서버는 루프백 주소에만 바인딩합니다. 원격 공개 접근을 활성화하지 마세요. 향후 원격 사용은 단일 사용자 인증과 서버 접근 통제가 먼저 필요합니다.

```sh
npm run build     # TypeScript 검사와 프로덕션 빌드
npm test          # 계산, 복원, URL, CSV, IndexedDB 검증
npm run test:e2e  # PC 1440px, 모바일 390px의 실제 브라우저 흐름
npm run preview  # 빌드 결과 로컬 확인
```

E2E는 이 환경에 설치된 `/usr/bin/chromium`을 사용합니다. 다른 시스템에서는 Chromium 설치 경로를 `CHROMIUM_PATH`로 지정하세요. 브라우저·운영체제의 클립보드 권한이 없으면 검색어를 직접 복사할 수 있습니다.

## 구현 기능

- 대시보드, 새 제품 발견, 제품군 탐색, 후보 목록·상세, 시장 검증, 총판 검토, 설정 메뉴
- 가상 제품 12개와 가상 콘텐츠. 분야·작성자·반복 구매 유형을 다양하게 구성하고 시연 표시. 가짜 SNS URL은 제공하지 않음. 시연 반응 수치·차트는 가상 수치로 식별
- 시연 모드와 사용자 작업 모드 분리. 시연 삭제 후 재실행 시 자동 복원하지 않으며 사용자 입력 보존
- 플랫폼·언어·카테고리·작성자·반복 구매·기간·주제·구매자 시장 필터. 게시일/구매자 시장이 미확인인 콘텐츠는 해당 구체 조건에 일치하지 않음
- 내장 사전: 친환경 주방세제, 커피, 반려동물, 화장품, 정수필터, 원예, 프린터. 제안된 탐색어 편집, 외부 검색 이동, 인스타그램용 검색어 복사, 조건 저장·재사용
- 지원하지 않는 제품군은 무관한 시연 결과를 반환하지 않음. 해외 검색어 직접 입력·외부 검색·직접 후보 등록으로 진행 가능
- 후보 등록·수정·삭제·검색·상태 필터·정렬·최대 4개 비교. 상태 이동 순서를 강제하지 않으며 보류·제외 이유 기록
- 제품과 콘텐츠 별도 저장, 여러 콘텐츠 연결, 콘텐츠 편집·삭제·다른 후보로 이동. 동일 URL의 추적 파라미터를 제거하여 중복 감지 후 기존 후보 이동 제안. 이름 기반 자동 병합 없음
- 제품이 불확실하면 임시 후보명으로 등록하고 나중에 편집·콘텐츠 재연결
- 제조사 국가, 판매 시장, 콘텐츠 언어, 작성자 소재지, 실제 구매자 시장을 별도 기록. 빠진 지표는 ‘미확인’
- 제품군·브랜드 검색어 분리, 날짜별 조사 기록과 출처, 명시적 CSV 양식 가져오기, 표·차트. 지표별 기록 분리
- 총판권·MOQ·공급/결제/납기·수입 절차 메모·접촉 이력. 연락 자동 발송 없음
- 사용자 환율·원가·배송·수수료·광고·반품 비용에 따른 단위 이익과 이익률, 계산 내역. 부가세 제외 기준, 회수 가능 부가세는 별도 메모. 관세·세금 자동 판정 없음
- 판매 테스트 기록과 전환율·손익. 방문수 0/누락 시 전환율 계산 불가, 비용 누락 손익은 잠정치
- JSON 전체 백업·형식 검증·확인 후 원자적 복원. 후보 CSV 내보내기와 스프레드시트 수식 주입 방지

## 저장·백업

현재 브라우저의 IndexedDB `marketing-trend-local` 데이터베이스 `workspace` 저장소를 사용합니다. 서버나 클라우드 계정에 동기화하지 않습니다. 동일한 브라우저·출처(호스트/포트)를 사용해야 같은 기록을 읽습니다. 브라우저 저장소 삭제나 다른 포트 사용 시 데이터가 없어 보일 수 있습니다.

설정·데이터 관리 → **JSON 전체 내보내기**로 백업하세요. 전체 JSON은 시연·사용자 후보, 콘텐츠, 조사·접촉·판매 기록, 검색 조건, 카테고리와 시연 삭제 상태 및 SNS 관측·댓글 근거·홈페이지 점검·AI 노출 기록을 포함합니다. **JSON 전체 복원**은 버전·필드·연결 관계를 먼저 검증하고, 확인을 받은 뒤 한 번의 IndexedDB 쓰기로 교체합니다. 잘못된 파일은 기존 데이터를 변경하지 않습니다. 후보 CSV는 목록 전달용이며 전체 복원용이 아닙니다. 백업에는 직접 입력한 업무 연락처와 메모가 포함될 수 있으므로 개인 파일로 보관하세요.

지원 시계열 CSV는 UTF-8의 `date,value` 헤더와 `YYYY-MM-DD,0 이상의 숫자` 행입니다. 외부 서비스 전용 CSV 자동 해석기는 아닙니다.

```csv
date,value
2026-01-01,20
2026-02-01,35
```

## 미연결 기능과 확장 위치

Instagram 계정명 기반 조회는 아래 별도 절차로 제공하며, 일반 SNS 키워드 검색·해시태그 검색·실시간 검색량/환율·AI 번역/분석·실제 주문 연동은 제공하지 않습니다. 네이버 도구 등 일부 외부 링크의 실제 사용에는 해당 제공업체 계정이 필요할 수 있지만 앱의 로컬 흐름에는 필요하지 않습니다.

- `src/providers.ts`: 외부 공급자 인터페이스와 연결 상태 (`미연결 / 시연 / 연결됨 / 오류`)
- `src/domain.ts`: 저장 구조, 계산·CSV·복원 검증과 내장 사전/시연 데이터
- `src/store.ts`: IndexedDB 읽기·쓰기. 향후 서버 저장 구현을 분리할 위치
- `src/App.tsx`: 한국어 화면·작업 흐름

향후 비밀키가 필요한 연동은 서버에서 처리해야 합니다. 브라우저 저장소나 공개 번들에 비밀키를 넣지 않습니다. 현재 데이터 스키마는 버전 2이며 버전 1을 자동 이전합니다.

## 검증 범위

단위 테스트는 수익 배분·부가세 제외·누락값, 전환율, 잘못된 백업과 연결 관계, CSV, URL 정규화, 알 수 없는 제품군, 저장 유지·시연 삭제를 검증합니다. 브라우저 테스트는 제품군 탐색, 후보 등록·상태 수정·새로고침 유지, 콘텐츠 연결·중복 감지, 조사 CSV, 원가 계산, JSON 다운로드·복원과 잘못된 파일 보존을 PC·모바일에서 실행합니다. 외부 API 동작이나 실시간 SNS 데이터의 정확성을 검증하는 테스트는 아닙니다.

## SNS·홈페이지·AI 근거 확장 (버전 2)

후보 상세에 접을 수 있는 기본 정보·SNS 관측 이력·댓글 근거·시장 검증·홈페이지 SEO·GEO 점검·AI 답변 노출 기록·다음 조사 과제를 제공합니다. 기존 비교·시장 검증·총판·원가·판매 테스트 기능도 유지합니다.

- SNS 관측은 별도 불변 스냅샷을 추가합니다. 조회·좋아요·댓글·공유·저장·팔로워 수를 지표별 **확인됨 / 미확인 / 비공개 / 지원 안 됨 / 오류** 상태와 함께 저장합니다. 값이 없으면 null이며 확인된 0과 구별합니다. 지표의 원래 명칭·정의·출처·수집 방식과 시간대 포함 관측 시각을 보존합니다.
- 좋아요·댓글 비율은 같은 관측의 분자·분모가 확인되고 조회수가 양수일 때만 계산합니다. 조회수 순증감과 증가율, 실제 경과 시간 기준 일평균 순증감을 표시합니다. 이전 값 0·단일 관측·불명확한 시간은 관련 계산에서 제외합니다. 감소값을 유지하고 데이터 정정 가능성을 안내합니다.
- 콘텐츠 기본 정보에 플랫폼 ID·형식·광고 판단 근거/확인일·소재지/시장 근거를 추가했습니다. 플랫폼·형식·게시일 시작·최신 관측일로 필터링하고 확보된 지표로 정렬합니다. 미확인 수치는 마지막이며 플랫폼 간 고유 도달로 합산하지 않습니다. 작성자의 평소 성과 대비 비교는 비교 표본이 없어 제공하지 않습니다.
- 댓글은 수동 발췌·원문 출처·확인일·복수 분류·표본 수·선정 방식·메모를 기록하고 편집·삭제합니다. ‘확인한 댓글 표본 기준’이며 전체 댓글이나 실제 주문으로 일반화하지 않습니다. 작성자 개인정보는 별도로 수집하지 않습니다.
- **홈페이지 SEO·GEO 점검**은 URL별 15개 항목의 상태·근거와 문제·권장 수정·처리 상태를 누적하고 편집합니다. 자동 크롤링·색인 확인·AI 추천 확률 계산은 하지 않습니다. 구조화 데이터와 실제 본문 일치, robots/noindex 해석의 한계를 안내합니다.
- **AI 답변 노출 기록**은 질문·서비스/모델·소비자용 화면/API·검색 여부·언어/지역·실행 시각·답변·언급/인용·인용 URL·경쟁 브랜드·오류/수정 과제를 수동 기록합니다. 정확히 동일한 조건끼리 묶고 등록 표본 내 분모를 표시합니다. 실패/미실행과 여부 미확인은 해당 비율에서 제외합니다. 언급과 인용을 추천으로 판정하지 않습니다.
- 후보 비교에 플랫폼별 관측 출처·최신성, 홈페이지 개선 과제, AI 표본 결과를 추가했습니다. 설정에는 검색/기본 정보/지표/댓글의 독립 능력·권한·대상 범위·한도·보관/갱신·오류를 표시합니다.
- **현재 모드 관측·출처 CSV 내보내기**는 시연/사용자 구분, 출처, 수집 방식, 지표별 상태·명칭·정의·관측 시각을 포함합니다. 댓글·페이지·AI의 전체 자료는 JSON 백업에 포함됩니다.

### 데이터 이전과 복원

앱 첫 로드 시 버전 1을 검증 후 버전 2로 이전합니다. 같은 IndexedDB 저장소의 `before-v2-migration` 키에 최초 이전 직전 원본을 보존하고, 새 state와 함께 한 트랜잭션으로 저장합니다. 제품·콘텐츠·시장/접촉/판매 기록·후보 원가/총판 필드·조건·카테고리·시연 삭제 상태를 유지합니다. 버전 1 JSON 복원도 같은 변환기를 사용합니다.

과거 조회수·좋아요·댓글 값은 최초 관측으로 이전합니다. 기존 관측값이 0이면 0을 보존합니다. 시간대 포함 시각이 있으면 그대로 사용하고, 날짜만 있으면 `originalObserved`에 날짜를 남기고 정확한 시각은 null로 둡니다. 관측일이 없으면 null/미확인을 유지하며 이전 실행 시각으로 위장하지 않습니다. 날짜만 있는 기록은 일평균 증가 속도 계산에서 제외합니다. 기존 데이터에 가상 관측을 추가하거나 사용자 데이터를 시연으로 덮어쓰지 않습니다. 새 설치·명시적인 시연 재추가에만 시연 관측을 제공합니다.

## 유튜브 실제 연결 준비와 남은 설정

로컬 수동·시연 흐름에는 키가 필요하지 않습니다. 실제 유튜브 조회만 다음 설정이 필요합니다. 이번 검증 환경에는 키가 없으므로 **실제 API 성공은 아직 검증하지 않았습니다**. 단위 테스트의 API 응답은 명시적인 모의 응답입니다.

1. 사용자가 관리하는 Google Cloud 프로젝트에서 **YouTube Data API v3**를 활성화하고 적절히 제한한 API 키를 준비합니다. 자동 회원가입·결제·OAuth 계정 연결은 수행하지 않습니다.
2. 클라우드 **환경 설정의 보안 값**에 `YOUTUBE_API_KEY`를 등록하고 HTTPS 목적지 `www.googleapis.com`을 허용합니다. 키를 채팅·소스·VITE_ 변수·브라우저 저장소에 넣지 마세요. 설정 반영 후 개발 서버를 재시작해 서버 프로세스에 주입해야 합니다. 저장한 초안은 실행 중 설정에 자동 적용되었다고 간주하지 않습니다.
3. `npm run dev`는 Node.js의 환경 프록시 지원(`--use-env-proxy`)과 Vite의 서버 전용 미들웨어를 사용합니다. `GET /api/youtube/status`는 설정 여부만 반환하며 키를 반환하지 않습니다. `GET /api/youtube/video?id=...`는 `videos.list(part=snippet,statistics)`에 서버 헤더로 키를 보냅니다. 공유·저장 수는 해당 공개 응답에서 미지원이며 누락된 좋아요·댓글은 미확인으로 보존합니다. Node.js 24와 신뢰된 플랫폼 CA·HTTPS 프록시 설정을 유지하세요.
4. **사용자 작업** 모드에서 실제 유튜브 URL 또는 11자리 ID를 등록합니다. 서버 키 설정이 확인될 때만 해당 콘텐츠 상세의 **공식 API 최신 지표 조회** 버튼이 나타납니다. 조회 성공 후 기본 정보·관측 스냅샷과 실제 조회수·좋아요·댓글 수를 검토하세요. 실패는 오류로 표시하고 기존 성공 기록을 보존합니다. 이 단계가 완료되어야 실제 연결 성공을 보고할 수 있습니다.
5. `npm run preview`도 같은 로컬 미들웨어를 사용합니다. 단순 `dist` 정적 호스팅만으로는 API 기능이 동작하지 않습니다. 원격 운영 시 서버 인증·접근 통제·키 제한·속도 제한·할당량 관리가 추가로 필요하며 이번 작업에서 공개 배포하지 않습니다.

후속 연결 순서는 **유튜브 기본 정보·반응 지표 → 유튜브 댓글 표본 → 인스타그램·틱톡 권한/대상 검토 → 홈페이지 수집 → AI 관측 자동화**입니다. 검색·지표·댓글은 독립적인 공급자로 연결하고 일부 실패 시 성공값은 보존합니다. API 데이터의 보관·삭제·갱신 주기는 제공업체의 최신 정책과 실제 권한에 맞춰 구현해야 합니다.

착수 전 최신 공식 문서와 발급 권한·할당량을 확인하세요: [videos.list](https://developers.google.com/youtube/v3/docs/videos/list), [statistics 정의](https://developers.google.com/youtube/v3/docs/videos#statistics), [commentThreads.list](https://developers.google.com/youtube/v3/docs/commentThreads/list), [YouTube API 정책](https://developers.google.com/youtube/terms/developer-policies). 이 버전은 인스타그램·틱톡 임의 공개 계정 전체 수집을 전제하지 않습니다.

추가 구현 위치: `src/research.ts`(지표/비율/이전/확장 검증), `src/Evidence.tsx`(기록 화면), `src/YoutubeImport.tsx`(서버 조회 UI), `server/youtube.ts`(키를 취급하는 서버 전용 어댑터). 서버 모듈을 클라이언트 코드에서 import하지 마세요.

추가 검증: 관측의 0/미확인/비공개, 시간대 순서·실제 간격·감소·분모 0, 이전 원본 보존·구버전 JSON·v2 왕복, 댓글 표본/복수 분류, 실패 AI 관측 제외, 서버 지표 부분 성공·키의 헤더 전달·403 오류 처리를 단위 테스트로 검증합니다. PC·모바일 브라우저에서 새 기록 등록·댓글 편집·페이지 점검·AI 반복 관측·새로고침·v1 실제 IndexedDB 로드를 기존 회귀 흐름과 함께 실행합니다.

## Instagram 계정명 기반 가져오기

**Instagram 계정으로 가져오기** 메뉴에서 계정명, `@계정명`, Instagram 프로필 URL을 입력하고 **게시물 가져오기**를 누릅니다. 기본 5개, 최대 20개입니다. 일반 키워드·해시태그 검색이 아니라, API가 지원하는 공개 비즈니스·크리에이터 계정의 게시물 조회입니다. 사용자 제공 검증 범위는 연결 계정 `ted2416`과 외부 전문 계정 `bluebottle`이며 모든 공개 계정의 지원을 보장하지 않습니다.

### 실행과 서버 환경변수

기존과 동일하게 Node.js 24에서 실행합니다. 별도 서버 프로세스나 DB 교체는 필요하지 않습니다.

```sh
npm ci --cache /workspace/.npm-cache
npm run dev -- --port 5173 --strictPort
```

운영자가 `.env.example`의 빈 이름을 참고하여 Git에서 제외되는 **저장소 루트 `.env.local`** 또는 프로세스/서비스의 **비밀 환경변수**에 값을 직접 설정합니다. Vite 설정은 허용된 서버 변수만 로드하며 `VITE_` 변수나 클라이언트 번들로 전달하지 않습니다. 변경 후 개발 서버를 재시작하세요. 클라우드 환경에서는 환경 설정의 보안 값 입력 기능을 사용할 수 있습니다. 토큰을 채팅·PR·소스·브라우저 저장소에 입력하지 않습니다.

| 서버 변수                | 용도                                                                  |
| ------------------------ | --------------------------------------------------------------------- |
| `INSTAGRAM_ACCESS_TOKEN` | 운영자가 보안 값으로 제공할 서버 토큰. 현재 개발 환경에는 없음        |
| `INSTAGRAM_USER_ID`      | 요청 주체 ID. 비어 있으면 사용자 제공 검증값 `17841403677011668` 사용 |
| `META_GRAPH_API_VERSION` | 비어 있으면 사용자 제공 검증 버전 `v26.0` 사용                        |

Meta 앱 ID `4259579541000688`은 연결 배경 정보이며 이번 조회 요청을 위해 앱 설정을 변경하지 않습니다. `me/accounts`나 계정 재연결에 의존하지 않습니다. 사용자 제공 토큰 만료 예정일은 **2026-12-19**이며 실제 활성 상태를 보장하지 않습니다. 인증 오류는 **Instagram 인증 만료 또는 해제 — 관리자 토큰 교체 필요**로 표시합니다. 자동 갱신은 구현하지 않았습니다.

서버가 접근할 HTTPS 목적지는 `graph.facebook.com`과 제공된 이미지의 `*.cdninstagram.com`, `*.fbcdn.net`입니다. 공식 문서 확인에는 `developers.facebook.com` 접근이 필요합니다. 환경 설정 초안 저장만으로 실행 중 정책이나 토큰이 적용되지는 않습니다. 이 작업 환경에서는 공식 문서 사이트가 403으로 차단되어 최신 썸네일 필드의 문서 확인을 완료하지 못했습니다. [IG Media 공식 문서](https://developers.facebook.com/docs/instagram-platform/instagram-graph-api/reference/ig-media/)를 접근 가능할 때 재확인하세요. 검증되지 않은 선택 필드는 기본 조회와 분리해 실패를 격리했습니다.

### 서버 경로와 지원 범위

- `GET /api/instagram/status`: 토큰 설정 여부·해시태그 승인 대기·자동 갱신 미구현만 반환합니다. 설정 여부는 연결 성공을 의미하지 않습니다.
- `GET /api/instagram/account?username=bluebottle&limit=5`: 서버에서 정규화·검증하고 고정된 Graph 경로와 fields만 사용합니다. 임의 경로·fields·커서는 입력할 수 없습니다. Meta 토큰은 서버 Authorization 헤더로만 전송합니다.
- 연결 계정은 검증된 `17841403677011668/media` 경로로, 외부 계정은 해당 ID를 주체로 한 `business_discovery.username(...)` 경로로 조회합니다. 연결 계정의 `views`만 게시물별 insights에서 시도합니다. 외부 계정의 인사이트는 호출하지 않으며 조회수는 **미확인 / 외부 계정 조회수 미검증** 사유로 보존합니다.
- 이미지 `media_url`, 영상 `thumbnail_url`, 캐러셀의 이미지 자식은 선택 조회로 분리합니다. 선택 필드 실패는 경고로 표시하며 기본 게시물·좋아요·댓글을 유지합니다. 이미지가 없으면 썸네일 미확보로 표시합니다. 영상은 VIDEO로만 식별하며 릴스 여부를 임의 확정하지 않습니다.
- `GET /api/instagram/thumbnail?id=...`: 서버 메모리의 무작위 ID로만 접근하는 이미지 중계입니다. Meta의 실제 CDN URL·paging.next·토큰 포함 URL은 응답에 넣지 않습니다. 허용 CDN·이미지 MIME·5MB 크기 제한·15분 만료·최대 200개 URL 보관을 적용하며 리다이렉트는 따라가지 않습니다. 이미지가 만료되면 다시 가져오세요. 서명된 이미지 URL은 브라우저 저장소에 보관하지 않습니다.
- 현재 미들웨어는 루프백·동일 출처 요청만 허용하고 가져오기를 분당 10회로 제한합니다. 외부 프록시 전달 요청은 거부합니다. **공개 배포·공유 터널은 하지 않습니다.** 원격 배포를 하려면 서버 인증·사용자별 요청 제한·신뢰할 프록시 구성을 먼저 구현해야 합니다. 단순 정적 `dist` 배포만으로 API는 동작하지 않습니다. `npm run preview`도 로컬 미들웨어를 포함합니다.

### 결과·저장·지표

프로필의 제공된 계정명·팔로워/게시물 수, 썸네일, 접을 수 있는 본문, 원본 콘텐츠 유형, 게시일, 좋아요·댓글·조회수의 값/상태/사유, 수집 시각, 원문 링크를 표시합니다. 누락 본문·이미지·수치는 만들지 않습니다. 실제 응답은 **실제 API 데이터**, 기존 가상 사례는 **시연 데이터**로 구분합니다. 댓글 개수만 조회하며 댓글 본문 수집은 포함하지 않습니다.

**후보 저장**은 사용자 작업 공간에만 저장합니다. 새 후보명은 **제품 미분류 콘텐츠**이며 계정명으로 상품·브랜드·전문가 유형·광고 여부를 자동 확정하지 않습니다. 기존 사용자 후보에 연결할 수도 있습니다. 같은 플랫폼+게시물 ID의 재수집은 기존 콘텐츠·후보·사용자 편집 제목을 유지하고 수집 시각이 있는 관측을 추가합니다. 동일 가져오기 결과의 반복 저장은 중복 스냅샷을 만들지 않습니다. 다른 시점의 재수집은 별도 스냅샷입니다. API 콘텐츠의 플랫폼/게시물 ID는 편집으로 변경할 수 없으며 제목 등 메모성 정보는 편집 가능합니다.

지표의 실제 `0`은 그대로 보존합니다. 누락·권한 부족·미지원·오류는 null과 상태·사유로 남깁니다. 권한 오류만으로 게시물이 비공개라고 확정하지 않습니다. 명시적인 비즈니스 전환 전 게시물 오류는 **조회 불가 — 비즈니스 전환 전 게시물**로 표시합니다. 인사이트만 실패해도 게시물·좋아요·댓글과 과거 관측은 유지합니다. 기존 버전 2 구조에 선택적인 지표 `reason`을 추가했으며 DB 초기화·전면 교체 없이 이전 백업도 계속 읽습니다. JSON과 지표 CSV에 상태·사유·출처를 포함합니다.

### 검증 상태와 남은 승인

**실제 API 통합 테스트 미실행.** 이 개발 환경에는 실제 토큰이 없어 `bluebottle` 실제 게시물 조회 성공을 주장하지 않습니다. 모의 Graph 응답을 사용하는 단위/브라우저 테스트로 입력 검증, 직접/외부 요청 구분, 0/누락/권한/전환 전 게시물, 썸네일 부분 실패, 중복 콘텐츠 방지·관측 추가, 편집·재시작 유지, 오류 안내, 토큰·paging/CDN URL 미노출을 확인합니다. 브라우저가 Meta API/CDN을 직접 요청하지 않는지도 검사합니다. 빌드에는 가짜 보안 검증 표식을 주입해 브라우저 파일에 포함되지 않음을 확인했습니다. 기존 YouTube 어댑터·후보/비교·시장/총판·백업 검증도 유지합니다.

운영자가 유효 토큰과 네트워크 설정을 적용하고 서버를 재시작한 뒤 `bluebottle`과 `ted2416`을 가져와 실제 제공 지표·시각을 확인해야 실제 통합 검증이 완료됩니다. **해시태그 검색은 Instagram Public Content Access 심사·승인 전까지 Meta 승인 대기**입니다. 앱 심사 제출·기술 제공업체 등록·Meta 설정 변경·재로그인·승인 우회는 이번 범위에 없습니다. API 데이터의 보관/갱신/삭제 정책도 실제 운영 전에 최신 Meta 정책으로 확인해야 합니다.
